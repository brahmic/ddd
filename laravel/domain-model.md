# Доменная модель на PHP

[Профиль](README.md).

## LAR-MODEL-01

Основания: [DDD-ENTITY-01](../core/domain-model.md#ddd-entity-01), [DDD-VO-01](../core/domain-model.md#ddd-vo-01), [DDD-INV-01](../core/domain-model.md#ddd-inv-01).

**Решение профиля:** доменные классы используют явные типы и скрывают изменяемое состояние. В модели нет `Illuminate`, Eloquent, HTTP Request, фасадов и обращений к контейнеру.

| Понятие | Реализация профиля |
| --- | --- |
| Сущность | Идентичность и методы предметных действий; состояние закрыто |
| Value Object | Проверка значений при создании, сравнение по значению, неизменяемое представление |
| Агрегат | Корень контролирует изменения внутренних объектов |
| Доменный сервис | PHP-класс с предметной операцией и явными зависимостями |
| Доменное событие | Объект факта без обязанности самостоятельно отправлять себя |
| Репозиторий | Контракт получения и сохранения агрегата |
| Фабрика | Конструктор, именованный метод или класс по сложности сборки |

`readonly` полезен для значений и DTO. Для сущности допустимы закрытые изменяемые поля и методы поведения. `private(set)` ограничивает доступ к записи, но не гарантирует неизменяемость внутри класса или вложенных объектов. См. [PHP: Visibility](https://www.php.net/manual/en/language.oop5.visibility.php). Версионные возможности синтаксиса проверяйте для PHP проекта.

## Создание и восстановление

Основание: [DDD-FACT-01](../core/domain-model.md#ddd-fact-01).

Новый объект создаётся по текущим правилам создания. Восстановление принимает существующую идентичность и состояние; оно не генерирует события создания и не повторяет внешние эффекты.

Eloquent-запись преобразуется в доменную модель в Infrastructure. Для сложного восстановления выделите mapper, который передаёт в модель типизированные значения. Доменные фабрики не получают Eloquent Model или соединение БД.

Неизвестный статус требует явного решения: ошибка данных, отдельное состояние или внешняя проекция. Автоматический переход к благоприятному статусу допустим только как подтверждённое бизнес-правило.

## Время, ошибки и сериализация

Основания: [ARCH-PORT-01](../core/boundaries.md#arch-port-01), [ARCH-CONTRACT-01](../core/boundaries.md#arch-contract-01), [ARCH-FAIL-01](../core/boundaries.md#arch-fail-01).

Текущее время передаётся значением из прикладного сценария или явного порта. Для неизменяемого времени подходит `DateTimeImmutable`; согласуйте часовую зону и точность хранения.

Доменные ошибки выражают отказ модели. Ошибка недоступности хранилища может принадлежать контракту порта, а не доменному пространству имён. HTTP-статусы и локализованный текст формируются на границе представления.

DTO создаётся прямым преобразованием модели или отдельным mapper. Домен не обязан предоставлять `toArray()`. Для внешнего контракта предпочтительны явно выбранные поля; доменный enum можно преобразовать в строку на границе.

**Проверка:** модель проверяется обычным PHP-тестом без Laravel. Примеры реализации приведены в [сквозном сценарии](example.md#модель).
