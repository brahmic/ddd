# Критерии архитектурного ревью в Laravel

[Профиль](README.md). Критерии конкретизируют [критерии ядра](../core/review-criteria.md) для принятого профиля Laravel. Область применения определяется связанными правилами и выбранными механизмами реализации.

## Устройство приложения

- Профиль и допустимые варианты реализации имеют определённую область действия — [LAR-PROFILE-01](README.md#lar-profile-01).
- Структура модулей и направления импортов сохраняют границы контекстов и слоёв — [LAR-STRUCT-01](structure.md#lar-struct-01).
- Domain представляет модель на PHP без зависимостей от Laravel и ORM — [LAR-MODEL-01](domain-model.md#lar-model-01).
- Контейнер собирает сервисные зависимости с подходящим временем жизни — [LAR-DI-01](application.md#lar-di-01).
- Используемые механизмы Laravel совместимы с версией целевого проекта.
- Параметры конфигурации доходят до адаптеров в нужных единицах и допустимых диапазонах — [LAR-CONFIG-01](operations.md#lar-config-01).

## Поведение и адаптеры

- Сценарий проверяет необходимые полномочия и вызывает предметное действие модели — [LAR-USE-01](application.md#lar-use-01).
- Репозиторий восстанавливает модель без побочных эффектов создания — [LAR-PERSIST-01](persistence.md#lar-persist-01).
- Все записи в одной транзакции используют одно и то же соединение с БД — [LAR-TX-01](application.md#lar-tx-01).
- Сохранение защищает состояние от потери конкурирующих изменений — [LAR-LOCK-01](persistence.md#lar-lock-01).
- Адаптер внешнего API переводит данные и ошибки в локальный контракт; повторы учитывают тип сбоя и повторяемость операции — [LAR-REMOTE-01](persistence.md#lar-remote-01).
- Срок жизни, ключи и инвалидация кэша соответствуют требованиям к свежести и доступу — [LAR-CACHE-01](persistence.md#lar-cache-01).
- Доставка внешних эффектов согласована с commit и требуемым восстановлением после сбоев — [LAR-EFFECT-01](application.md#lar-effect-01).

## Точки входа и проверки

- HTTP, CLI и Job вызывают прикладные сценарии с согласованными контрактами — [LAR-ENTRY-01](presentation.md#lar-entry-01).
- Обработка ошибок сохраняет различие между бизнес-отказами и техническими сбоями — [LAR-ERROR-01](presentation.md#lar-error-01).
- Полномочия задания и результат его повторной обработки определены контрактом — [LAR-QUEUE-01](presentation.md#lar-queue-01).
- Тесты инвариантов и изолированных сценариев выполняются без загрузки Laravel — [LAR-TEST-01](testing.md#lar-test-01).
- Интеграционные проверки подтверждают необходимые свойства адаптеров — [LAR-TEST-02](testing.md#lar-test-02).
- Архитектурные проверки контролируют зависимости принятого профиля — [LAR-TEST-03](testing.md#lar-test-03).
- FormRequest, VO и схема API согласованы на общих допустимых, недопустимых и граничных значениях — [LAR-VALID-01](presentation.md#lar-valid-01).
- Форма JSON, HTTP-статусы и заголовки соответствуют публичному контракту — [LAR-PROTO-01](presentation.md#lar-proto-01).
- Диагностика сохраняет необходимый контекст и причину сбоя без непреднамеренного дублирования записей — [LAR-OBS-01](operations.md#lar-obs-01).
- Команды и CI проверяют заявленные свойства и учитывают изменения влияющих на них файлов — [LAR-CI-01](operations.md#lar-ci-01).
