# Настройки, диагностика и автоматические проверки

[Профиль](README.md).

## LAR-CONFIG-01

Основания: [ARCH-COMPOSE-01](../core/boundaries.md#arch-compose-01), [ARCH-BUDGET-01](../core/boundaries.md#arch-budget-01), [TEST-ARCH-01](../core/testing.md#test-arch-01).

**Решение профиля:** параметры модуля имеют явный источник, единицы, диапазон и проверку подключения к потребителю.

| Параметр | Что определить |
| --- | --- |
| Timeout | Секунды, допустимое значение и общий срок сценария |
| Retry | Общее число попыток либо повторов; условия повторяемости |
| Delay | Единицы, последовательность задержек и предел |
| TTL | Единицы, свежесть данных, поведение при нуле |
| Rate limit | Число запросов, окно и субъект ограничения |
| Подключение | Поставщик, endpoint и область действия конфигурации |

В Laravel первый аргумент `Http::retry()` обозначает максимальное число попыток. Три попытки дают максимум два ожидания между ними. Проверяйте это в названиях параметров, комментариях и тестах. См. [HTTP Client: Retries](https://laravel.com/docs/13.x/http-client#retries).

Вынесите чтение `env()` в конфигурационные файлы; дальше используйте готовую конфигурацию или переданные значения. Проверьте сборку при кэшировании конфигурации, если этот режим применяется: после `config:cache` Laravel не загружает файл `.env` обычным образом. См. [Configuration Caching](https://laravel.com/docs/13.x/configuration#configuration-caching).

**Проверка:** изменённый TTL даёт ожидаемый момент истечения на фиксированных часах, а изменённый timeout попадает в HTTP-клиент. Проверка типа аргумента или `instanceof` адаптера не подтверждает его настройку.

## LAR-OBS-01

Основания: [ARCH-OBS-01](../core/boundaries.md#arch-obs-01), [ARCH-FAIL-01](../core/boundaries.md#arch-fail-01).

**Решение профиля:** назначить место регистрации сбоя и отделить его от renderer ответа. При переносе в CLI и очередь диагностическая запись должна сохраняться и без HTTP.

Laravel разделяет reporting и rendering, поддерживает контекст исключения и управление повторным логированием. См. [Error Handling](https://laravel.com/docs/13.x/errors). Контекст записи также поддерживается системой [Logging](https://laravel.com/docs/13.x/logging#contextual-information).

Запишите минимальный состав события: имя сценария, идентификатор выполнения, категория ошибки, зависимость и число попыток — насколько это применимо. HTTP-URL, входные данные и тело ответа поставщика проходят собственную политику отбора; исключение поля из одного массива не удаляет его копию из URL или текста исключения.

Внутренние диагностические сведения не должны исчезать только потому, что выключен подробный ответ клиенту. Уровень записи выбирайте по смыслу: ожидаемый отказ и сбой инфраструктуры могут иметь разный уровень.

**Проверка:** логгер подменён принимающим сообщения объектом или тестовым каналом; проверены состав, причина и число записей. Ранний возврат для окружения testing проверяет отключение записи, но не её правильность.

## LAR-CI-01

Основания: [TEST-ARCH-01](../core/testing.md#test-arch-01), [TEST-CONTRACT-01](../core/testing.md#test-contract-01), [ARCH-DEC-01](../core/principles.md#arch-dec-01).

**Решение профиля:** команды и CI проверяют заявленные свойства проекта и запускаются при изменении соответствующих файлов.

- Для кода — тесты поведения, интеграции и принятых зависимостей.
- Для API — соответствие схем и примеров наблюдаемым ответам.
- Для документации — актуальность ссылок и примеров.
- Для конфигурации сборки — значимые параметры и поддерживаемый режим запуска.

Путь запуска workflow должен учитывать его собственный файл и другие влияющие входы. Выберите фильтры согласно устройству репозитория.

Если покрытие имеет обязательный порог, отдельно проверяйте порог и ошибки раннера. Генерация и публикация HTML-отчёта подтверждают наличие артефакта. Они не означают, что любое требование к покрытию автоматически выполнено.

**Проверка:** безопасный просмотр команд выявляет ошибки раскрытия переменных до установки. Lock-файл и фактическая платформа согласованы; установка с отключёнными проверками платформы не считается доказательством совместимости. Повтор установки не должен без необходимости менять существующие ключи и настройки проекта.
